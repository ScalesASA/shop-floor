Explainer

First Bot

Setup is a message, not a workflow builder. Official advice: a focused Bot builds more useful context than one catch-all helper. An account can hold up to 50 Bots and group chats combined.

TL;DR

Give it a short name, one primary job, and a description of how it should work. The first task states outcome, sources, constraints, deliverable, and where it must stop for you.

Official pattern from Cursor / xAI get-started:

Name: Piper
Job: Product performance
Description: Investigate product-performance questions with our
observability tools. Preserve links and screenshots, separate
evidence from hypotheses, lead with the highest-impact issue.
Never change production settings.
Step 1 — Write the description as policy

Description = rules that remain true next month. Message = this week’s list. If you put “draft the March email” in the description, the Bot will keep trying to be March.

Step 2 — First-task contract
  1. Outcome — what is finished?
  2. Sources — which apps, pages, files?
  3. Constraints — what must it avoid or ask?
  4. Deliverable — what does it return?
  5. Review point — when does it stop?

Every official starter prompt ends at a review point on purpose.

Step 3 — Correct in the conversation, promote to description

When a preference should survive this job (“five bullets, source links inline”), say so and then edit the profile. Do not hope memory will hold a safety rule. Safety goes in the description.

Stop-line. First Bot may read and draft. It may not send, publish, purchase, or change production.

Generic drill

15 minutes in the Grok Bot app. Create one Bot for a generic SMB (bakery, shop, clinic — pick one). Name + job + description with a never-line. Attach any PDF you have and run: summarize in five bullets; list dates and open questions; cite the section; do not change the file.

Personal build — FireGuard

Create this Bot, do not connect the CMS

Name: FireGuard
Job: Blue SteelCo EHS weekly scan
Description: Scan OSHA / NFPA / customer-facing storage questions
for fire extinguisher racks, pit handrails, and power-gen pit
compliance. Produce a weekly EHS brief: what changed, who it
affects, and one recommended site or content action. Separate
regulation text from interpretation. Never change product copy
live, never file an attestation, never email a safety manager.
Stop at the brief and a draft FAQ.

First task:

Open bluesteelco.com as a reader. List the product claims that
would need an OSHA or NFPA cite if an EHS manager asked
“says who?” Return a table: claim | page | cite needed | risk.
Do not log into Wix. Do not edit the site.
Done when FireGuard returns a table you could hand a reviewer without wincing.
